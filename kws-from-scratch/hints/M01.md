# M1 提示：配置、seed、provenance、日志

## 1. `with_overrides` 不知道从哪下手

<details><summary>提示 1</summary>

frozen 对象改不了，所以别想“改”，要想“重建”。Pydantic 对象可以变成普通 dict，普通 dict 可以随便改，然后再用 dict 构造一个新对象。

</details>

<details><summary>提示 2</summary>

需要的 API：`model_dump()`、`str.split("=", 1)`（为什么是 1？想想值里有等号的情况）、`str.split(".")`、`yaml.safe_load`（用来把字符串 "32" 变成 32）、`model_validate`。

</details>

<details><summary>提示 3</summary>

对每一条覆盖：检查有没有等号，没有就报 ValueError → 拆成键和值 → 键按点号拆成路径 → 在 dict 里沿路径走到倒数第二层 → 检查最后一个键在不在这一层里，不在就报 KeyError → 把值交给 YAML 解析后放进去。全部改完后，用整个 dict 重新构造 Config，所有 validator 会在这时自动重新运行。

</details>

## 2. `test_validators_run_after_override` 不过

<details><summary>提示 1</summary>

有三种不同的校验方式：字段类型本身（Literal）、字段约束（Field 的参数）、跨字段约束（model_validator）。看看失败的是哪一条，它属于哪一种。

</details>

<details><summary>提示 2</summary>

`Field(ge=..., le=...)`；`@model_validator(mode="after")` 装饰的方法拿到的是已经构造好的对象，检查不通过时 raise ValueError，最后要 return self。

</details>

## 3. 哈希每次运行都不一样

<details><summary>提示 1</summary>

Python 内置 `hash()` 对字符串加了随机盐（查 PYTHONHASHSEED）。你需要一个“密码学哈希”，它对同样的字节永远给同样的结果。

</details>

<details><summary>提示 2</summary>

`hashlib.sha256(字节).hexdigest()`。字节从哪来？把配置变成 JSON 字符串再编码。JSON 里键的顺序要固定。

</details>

## 4. provenance 在非 git 目录里崩溃

<details><summary>提示 1</summary>

运行失败的命令有两种失败方式：命令运行了但返回非零退出码；命令根本不存在。分别是哪两种异常？

</details>

<details><summary>提示 2</summary>

`subprocess.run(..., cwd=..., capture_output=True, text=True, check=True)` 失败时抛 `CalledProcessError`；git 不存在时抛 `FileNotFoundError`。写一个小的辅助函数，两种都捕获，返回 None。

</details>

## 5. logger 写不进 tensor

<details><summary>提示 1</summary>

json 只认识 Python 原生类型。0 维 tensor 和 numpy 标量都有一个共同的方法，可以变成 Python 数字。

</details>

<details><summary>提示 2</summary>

`.item()`。用 `isinstance(v, torch.Tensor)` 和 `isinstance(v, np.generic)` 判断。

</details>
