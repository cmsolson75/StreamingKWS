# 从读懂 StreamingKWS 到从零写出 ML 架构：24 周学习计划

**最终目标：** 面对一个新任务，只查官方文档、不看旧代码、不让 AI 写代码，也能独立搭出“数据 → 模型 → 训练 → 评估 → 部署”的完整系统，并能解释每一处设计。

**时间假设：** 每周 10–12 小时，共 24 周。时间不同就等比例伸缩，但不要跳过验收。

**这份计划能带你到哪：** 学完后，你应该能独立做中小型单机训练系统。“成熟的 ML engineer”还需要真实线上系统、团队 code review 和大规模训练的经验，这些只靠自学计划给不了。第 8 阶段之后的路线会提到。

## 1. 先定规则

这个 repo 的 `noel_learning` 分支已经有大量逐行注释。它们能帮你读懂代码，但也容易造成“看懂了就是会了”的错觉。所以整个计划围绕**闭卷重写**展开。

**闭卷：** 不看本 repo，不问 AI，只能查官方文档和自己的错题本。

### 每个知识点走五步

1. **读：** 只读当前要用的那一小段代码或文档。
2. **预测：** 运行前写下输出、shape 或数值。
3. **验证：** 运行或打断点，对照预测。
4. **闭卷写：** 关掉参考，在空文件里从头写。
5. **隔天再写：** 第二天再闭卷写一遍最核心的部分。写不出来就记入错题本。

### AI 使用规则

| 场景 | 可以 | 不可以 |
|---|---|---|
| 学概念 | 让 AI 出题、提问、解释你已经尝试过的内容 | 还没想过就直接要答案 |
| 写练习 | 写完后让 AI review，只指出问题在哪 | 让 AI 写、补全或“帮你改好” |
| 调 bug | 自己卡住 30 分钟后，要一个提示 | 把报错贴过去要修复后的代码 |
| 闭卷和毕业考试 | 不用 AI | 关掉编辑器里的 AI 补全 |

### 每周节奏（约 11 小时）

| 时间 | 内容 |
|---|---|
| 2 小时 | 学概念、读文档 |
| 6 小时 | 闭卷写代码、写测试 |
| 2 小时 | 跑实验、调 bug |
| 1 小时 | 周复盘：闭卷重写上周最弱的一个函数，并更新错题本 |

继续用 [知识点清单.md](知识点清单.md) 做错题本。每条记录三件事：**错在哪、为什么、以后怎么验证**。

### 代码放哪里

- **`kws-from-scratch`（新建空 repo）：** 放闭卷写的全部代码。这是你的主线作品。
- **本 repo：** 只当参考和修 bug 的练习场。每个 bug 单开一个分支。

### 阶段 4：模型与训练系统（第 12–15 周）

**目标：** 在 `kws-from-scratch` 里写出完整可恢复的训练系统。这是全计划最核心的一段。

**顺序不能乱：** 每一步验证通过再加下一步。

1. **模型：** 只看论文，写 CNN 和 TC-ResNet8。先用形状测试和参数量检查。
2. **跑通：** 最简训练循环，不加任何技巧。
3. **过拟合一个 batch：** 关掉 dropout 和增强，loss 要能接近 0。做不到就说明有 bug，先别往下走。
4. **加验证：** 再逐个加入 scheduler、梯度裁剪、AMP、EMA，每加一个都对比前后的曲线。
5. **加存档：** 模型、优化器、scheduler、scaler、EMA、采样器进度、随机数状态全部保存。

**要掌握的 API：** `nn.Conv1d`、`nn.Conv2d`、`nn.BatchNorm1d`、`nn.Dropout`、`AdaptiveAvgPool1d`、`torch.autocast`、`GradScaler`、`clip_grad_norm_`、`torch.save`、`torch.load`（以及 `weights_only` 的安全含义）、`safetensors`、`model.train()`、`model.eval()`、`torch.inference_mode`、`torch.profiler`

**EMA 要手写：** 先写两行公式版，并测试它能恢复。之后再读 `ema_pytorch` 的实现，对比它多做了什么。

**验收（恢复训练的严格测试）：** 在 CPU、`num_workers=0` 的条件下：

- A：连续训练 200 步。
- B：训练 100 步，保存，开新进程读取，再训练 100 步。
- 要求 A 和 B 的学习率完全相同，最终权重差在容差内。

这个测试一通过，你对“训练状态到底包含什么”的理解就真正到位了。

**repo 练习（先写会失败的测试，再修）：**

### 阶段 5：评估与实验方法（第 16–17 周）

**目标：** 从“准确率变高了”进步到“我能证明这个改动有效，也知道它在哪失败”。

- **KWS 指标：** repo 目前主要看准确率。你要加混淆矩阵、每类精确率和召回率、漏报率、每小时误报次数。
- **评估的可信度：** 验证和测试默认用 1000 个有放回抽样（见 [dataloaders.py:107](../../src/dataloaders.py#L107)）。算一下这种规模下准确率的误差范围，再改成完整遍历并比较。
- **实验方法：** 一次只改一个变量；多个 seed 对比；看 train 和 val 的差距判断过拟合；按 [调参手册](https://github.com/google-research/tuning_playbook) 确定顺序。
- **错误分析：** 听至少 50 条被分错的音频，按原因分类，再决定下一步改数据还是改模型。

**闭卷交付物：** 一份实验报告，包含消融实验（去掉增强、EMA、warmup、残差连接各一次，每组至少 3 个 seed）、结论和局限。

**验收：** 别人只看报告和 run 目录，就能复现你的结论。报告里要有至少一条“我原以为有用，实验显示没用”的记录，如果确实没有，就写清楚你验证了哪些假设。

**资源：** [Streaming keyword spotting on mobile devices](https://arxiv.org/abs/2005.06720)、[PyTorch ONNX](https://docs.pytorch.org/docs/stable/onnx.html)

### 阶段 7：Attention 与读论文写代码（第 21–22 周）

**目标：** 把能力从 CNN 扩展到现代架构，并练习“论文 → 代码”。

- 跟完 Zero to Hero 的 GPT 部分，再闭卷写出 self-attention、多头注意力、位置编码和 Transformer block。
- 写形状测试和因果 mask 测试：改变未来的 token，不应影响当前位置的输出。
- 把 Transformer 接到你的 Mel 特征上，和 TC-ResNet8 比较参数量、准确率、延迟。

**读论文的固定流程：** 先自己读，写下每个模块的输入输出 → 列出论文没说清的细节 → 自己实现 → 最后才对照官方代码或 [nanoGPT](https://github.com/karpathy/nanoGPT)，记录差异和原因。

**验收：** 模型能过拟合一个 batch，能闭卷在白板上画出一个 block 内部每一步的 shape，并有一份和 TC-ResNet8 的对比表。

**资源：** [Attention Is All You Need](https://arxiv.org/abs/1706.03762)、[nanoGPT](https://github.com/karpathy/nanoGPT)

### 阶段 8：毕业考试（第 23–24 周）

**题目：** 在新的空 repo 里，用 [ESC-50](https://github.com/karolpiczak/ESC-50) 做环境声音分类，模型用你在阶段 7 学到的结构，或另选一篇没实现过的论文。换任务是为了防止你靠记忆默写 KWS。

**规则：** 只能查官方文档和论文，关闭 AI 补全。全部写完后才可以让 AI review。

**必须包含：** 配置系统、实验记录、数据管线（按官方 5 折交叉验证）、训练循环、完整恢复、基线模型对比、错误分析、推理 CLI、测试。

**合格标准：**

- [ ] 一行命令能从空环境跑到训练开始。
- [ ] 恢复训练的严格测试通过。
- [ ] 新模型的 5 折结果和你自己的简单基线有可信比较，无论谁赢都能解释原因。
- [ ] 随机打开任一文件，能讲清每个设计决定和替代方案。
- [ ] 重做第 0 阶段的摸底题，并在 30 分钟内写完。

**之后怎么走向“成熟”：** 找人 review 你的代码（`teach` skill 也会建议你找社区），给开源项目提 PR，再学分布式训练（DDP）、线上监控和数据版本管理。这些最好放到真实项目里学。
